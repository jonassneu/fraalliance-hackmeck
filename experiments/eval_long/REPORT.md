## Setup

- **Periods** (`fra/evalkit.py`, single source of truth): long test from **2026-06-01** (default for all walk-forward evaluations), legacy test from **2026-09-15** (hackathon period), locked holdout from **2026-11-01**. The production spec was selected on the walk-forward from **2026-09-15** (`evalkit.SELECTION_START`), so the long test is split into the part not used for selection (valid < 2026-09-15) and the selection period (issue ≥ 2026-09-15).
  - Long test: issue 2026-06-01 .. 2026-10-30 10:00, valid until 2026-10-30 11:00 UTC; 152 valid days, 14465 scored OD rows at 1/6/24/48 h.
  - Legacy test: issue 2026-09-15 .. 2026-10-30 10:00, valid until 2026-10-30 11:00 UTC; 46 valid days.
- **Holdout lock:** rows with issue ≥ 2026-11-01 *or* valid ≥ 2026-11-01 are never scored by default (fra.train, harness, changetime). `python -m fra.train final`, `harness.evaluate(..., final=True)` and `python -m fra.changetime --final` score ONLY the holdout, each week trained strictly on earlier data (changetime uses the frozen PARAMS / P48_COEF). No holdout rows exist yet (labels end 2026-10-30 11:00 UTC).
- **Folds:** week w = issue in [start + 7w d, start + 7(w+1) d), training rows = labels known at the week start (valid + KNOWN_LAG_H <= week start; with the hackathon lag of 1 h: valid < week start). Identical to the hackathon's "valid < first issue of the week" on both periods (checked: the first issue of every week equals the calendar week start).
- **Error bars:** day-block bootstrap (2000 reps, seed 20261031): whole UTC days of valid time are resampled; the same resampled days are used for every method and lead, so paired differences are on identical rows. Brackets = 95 % percentile interval. All methods are scored on exactly the same rows.
- **Baselines:** official rules (case section 3 on the ECMWF forecast tailwind), published Umwelthaus prognosis (main scenario ≥ 0.5, persistence where missing), persistence (OD of the last complete radar hour, fra.dataset.last_complete_hour).
